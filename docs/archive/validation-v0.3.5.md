# 0.3.5 Windows 更新恢复验证

本版实现一次性原生更新交接、应用外的稳定发布缓存、隐藏启动检查、当前用户快捷方式备份和恢复，以及同版本 ASAR 和后台事务。原生语音设置源文件与已认可的 0.3.4 字节一致；录音和文本处理行为保持原样。

候选自动检查已完成：94 项 Node 检查、57 项 Python 检查、24 项真实原生控件的隔离浏览器检查，以及 24 项语音交互浏览器检查。TypeScript、39 个 JavaScript 源文件及 CI YAML 通过检查。PowerShell 脚本经过 Windows PowerShell 5.1 解析和实际隔离执行，Pythonw 源文件通过语法检查。

Windows WSH 隔离测试实际创建自有临时快捷方式，覆盖包含空格的路径和参数、图标及元数据保留、重复绑定、模拟官方更新重建入口、回退、人工修改拒绝和多项保存中途失败。故障注入先确认第一条快捷方式确实完成保存，再让第二条失败；失败后，两条快捷方式与此前不存在的 receipt 状态全部恢复。回退自身失败也恢复部署状态，并支持修复备份后再次回退。

使用本机保存的真实 1.18.33 与 1.18.34 ASAR，完成隔离升级模拟。恢复助手等待安装进程子树与文件稳定后补回 1.18.34，保留配置、释放锁、完成一次重绑定和启动回调。回退结果与 1.18.34 官方原包字节一致。这里的进程、安装程序及启动动作使用替身，没有运行真实更新安装程序。

1.18.34 候选的 6953 个 packed 条目均通过完整性检查，重复生成字节一致。从 0.3.4 升级时只有 main 和录音脚本两项改变，新增 update bridge 一项，其余 6950 项 packed 数据保持原字节；原生设置模块保持原字节。

Windows PowerShell 5.1 的参数引号差异已改为外部 CLI 调用。Node 调用 Windows PowerShell 时清除子进程继承的 PSModulePath，避免 PowerShell 7 的模块路径影响系统进程查询；不会改动系统环境变量。

本机隐藏启动检查发现 Win32_Process 返回 PID 0 的系统空闲进程，曾导致恢复身份解析失败。进程协议现在排除此项，并通过真实 Windows 查询验证所有记录可解析且包含测试进程；其余不可用身份仍明确报错。

本轮没有实际麦克风、实际语音、外部 AI、模型冷启动或真实未来官方升级测试。未知应用布局、未知安装程序行为、管理员更新均有明确拒绝边界；不能把这些验证称作任意未来 OpenCode 版本永远兼容的保证。

本机安装后的清单、同版本备份、文件回读、真实助手握手和启动证据保存在本机维护目录及 test-results，不放入发布包。真实未来升级和语音体验交由用户验收。
